4. **HOBBY-P01~P03 · SHORT-P01 · TODO-P01 콘텐츠 원본(10/26)** → **SYS-B15 시드 적재** → 추천·시작하기·숏폼 수집 개발. 관리자 편집 화면이 제외(P2)라 취미 콘텐츠·분류·태그·TODO 원본·데이터 매핑표·신뢰 채널은 MVP 내내 시드 SQL(또는 DB 직접 수정)로 넣고 고칩니다. 원본이 없으면 시작하기와 TODO가 동작하지 않습니다.

## 표기
- **ID**: `도메인-파트번호`. 파트 F = 프론트엔드, B = 백엔드, P = 기획·운영. 같은 도메인의 F·B 작업이 짝입니다.
- **우선순위**: 기능 요구사항 CSV(`../spec/feature-requirements.csv`, 10/21) 기준입니다.

| 등급 | 뜻 | 일정 | 작업 목록 표기 |
|---|---|---|---|
| P0 | 필수(MVP) | 11/04 개발 마감 | `필수` |
| P1 | 권장(MVP) | 11/09~11/12 개선 기간 | `권장` |
| P3 | 후순위 | P0·P1을 마친 뒤 시간이 남으면(개선 기간 안에 못 하면 발표 이후) | `후순위` |
| P2 | MVP 제외 | 이번 개발 범위에서 뺌, 고도화 후보로만 남김 | `제외` |

- **개발 순서**: P0 → P1 → P3이고 P2는 개발하지 않습니다(번호 순서와 다름에 주의). 기존의 'P1 고도화'는 없어졌고, 서비스 피드백(FR-FB-01·02)은 CSV에서 빠져 제외(P2)입니다.
- **우선순위가 섞인 작업**: 가장 앞선 등급(필수 > 권장 > 후순위 > 제외)으로 표기하고, 등급이 낮은 부분은 본문에 `[P1]`·`[P2·MVP 제외]`·`[P3]`로 표시하고 비고에 적습니다.
- **제외 작업의 진행표기**: 엑셀에서 우선순위 `제외` 작업은 진행표기도 '제외'로 두어 완료율·진행률 분모에서 뺍니다.
- **근거**: 명세서 기능 ID(FR-\*)·비기능 ID(NFR-\*)·장 번호. 근거 항목의 규칙·예외가 곧 완료 기준(QA 체크리스트)입니다.
- **11장 #N**: 명세서 11장 '결정할 것'에 걸린 작업. 결정이 바뀌면 작업 내용도 같이 고칩니다.
- **체크박스**: 진척의 기준은 엑셀의 `진행표기`(완료·부분·미착수·제외)입니다. MD 체크박스는 MR을 올릴 때 같이 체크하는 용도로 씁니다.
